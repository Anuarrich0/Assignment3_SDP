# Assignment 3 — объяснение задания и готового решения

## Что от тебя хотят

Нужно написать **одну программу**, в которой Bridge и Adapter решают разные части
одной задачи. Нельзя просто сделать отдельную демонстрацию Bridge и отдельную Adapter.
К программе нужны тесты JUnit 5, UML-картинка, короткое обоснование и устная защита.
Защита — **50% всей оценки**. Поэтому важно уметь пройти по коду одного запроса.

Тема решения: приём музейных образцов. Сотрудник указывает коллекцию, номер образца,
название и режим приёмки. Программа регистрирует образец в подходящем каталоге.
Это учебная модель: настоящей базы данных, музейного сервера и физического карантина нет.
Тридцать дней — выбранное правило демонстрации, а не научная рекомендация.

## 1. Overview — одна связанная система

Есть две независимые вещи, которые могут меняться:

1. **Правило приёмки:** обычная регистрация или регистрация с карантином.
2. **Каталог:** центральный каталог, полевой журнал или старый архивный реестр.

Любое правило должно работать с любым каталогом. Получаем 2 × 3 = 6 комбинаций.
Bridge позволяет собирать эти комбинации из объектов. Adapter подключает старый
реестр к тому же интерфейсу, которым пользуются оба правила.

## 2. Learning Objectives — чему учит задание

**Bridge:** разнести две иерархии, чтобы они развивались независимо. В программе это
`Accession` с наследниками и `SpecimenCatalog` с реализациями.

**Adapter:** использовать несовместимый класс без изменения его исходника.
`LegacyLedger` не знает о `SpecimenCatalog`; перевод делает `LegacyCatalogAdapter`.

**Почему нужны оба:** Bridge разделяет политику и инфраструктуру, но сам по себе не
превращает байты и числовые ошибки старого API в современный контракт. Adapter делает
такой перевод, но сам по себе не создаёт независимую иерархию правил приёмки.

**Open/Closed Principle:** добавлять новое поведение расширением, сохраняя существующую
логику. Новый режим наследуется от `Accession`; новый каталог реализует `SpecimenCatalog`.
Оба передаются через реестры в конструктор `IntakeService`.

## 3. Mandatory Requirements — каждый обязательный пункт

### 3.1. Собственная предметная область

Предметная область — то, о чём программа: здесь музейные образцы и их приёмка.
В найденных локальных Assignment 1 и 2 темы — туристические пакеты и игровой мир.
Музейная тема от них отличается. Нужно самостоятельно подтвердить, что она не
повторяет чужую работу или пример на занятии, которого нет в предоставленных лекциях.

### 3.2. Bridge: минимум два Refined Abstractions и три Implementors

| Термин | Класс | Что делает |
|---|---|---|
| Abstraction | `Accession` | Хранит ссылку `catalog` типа `SpecimenCatalog` |
| Refined Abstraction 1 | `StandardAccession` | Регистрирует с карантином 0 дней |
| Refined Abstraction 2 | `QuarantineAccession` | Регистрирует с карантином 30 дней |
| Implementor | `SpecimenCatalog` | Объявляет общий метод `register` |
| Concrete Implementor 1 | `CentralCatalog` | Хранит записи в индексированном `Map` |
| Concrete Implementor 2 | `FieldJournal` | Дописывает записи в список журнала |
| Concrete Implementor 3 | `LegacyCatalogAdapter` | Переводит вызовы для старого реестра |

Связь Bridge находится в `Accession`:

```java
protected final SpecimenCatalog catalog;
```

Это **composition**: один объект содержит ссылку на другой. Сам `Accession` не
наследуется от каталога. В UML здесь обычная направленная ассоциация: объекты
каталогов создаются снаружи и могут использоваться несколькими приёмками.

Метод `QuarantineAccession.admit`:

```java
return catalog.register(specimen, 30);
```

Приёмка выбирает правило, каталог выполняет регистрацию. Для нового каталога не нужны
`QuarantineCentralAccession`, `QuarantineFieldAccession` и другие комбинационные классы.

### 3.3. Ровно одна адаптированная реализация

Два каталога сразу реализуют наш интерфейс. Третий доступен через Adapter.
Сам `LegacyLedger` интерфейс не реализует и не считается четвёртым Implementor.

Современный контракт:

```java
String register(Specimen specimen, int quarantineDays) throws CatalogException;
```

Старый контракт:

```java
int accession(int holdDays, byte[] description, long number);
```

Отличается не только имя: объект распадается на параметры, порядок другой, название
становится массивом байтов UTF-8, строковый ID превращается в `long`, результат — число,
а ошибки возвращаются кодами. Adapter выполняет все эти преобразования.

`LegacyLedger` — самостоятельная учебная имитация старого компонента. Его исходник
зафиксирован; контрольная сумма записана в `legacy-contract.md`. Это не заявление о
том, что код получен от настоящего поставщика.

### 3.4. Abstraction зависит только от интерфейса

У `Accession` поле типа `SpecimenCatalog`, а не `LegacyLedger` или `CentralCatalog`.
Его наследники не импортируют legacy-класс и не проверяют `-1`, `-2`, `-3`.
Они знают только современную модель `Specimen` и общий `CatalogException`.

То, что `Main` создаёт конкретные классы, нормально: это место сборки приложения
(composition root). Где-то реальные объекты должны быть созданы.

### 3.5. Полный перевод ошибок

| Ответ старого API | Что видит остальная программа |
|---|---|
| Положительное число | Квитанция вида `ARCHIVE-19` |
| `-1` | `CatalogException` с причиной `DUPLICATE` |
| `-2` | Причина `INVALID_INPUT` |
| `-3` | Причина `UNAVAILABLE` |
| `0` или неизвестный отрицательный код | Причина `INTERNAL` |
| Неожиданный `RuntimeException` | Причина `INTERNAL`, без старого сообщения и cause |

Общие неверные аргументы также дают `INVALID_INPUT`. Старый реестр принимает номера
1..999999, максимум 80 байт названия и карантин до 365 дней. Общий контракт разрешает
каталогу отклонять неподдерживаемые данные единообразной ошибкой.

Номер `007` отклоняется: иначе при преобразовании в число он совпал бы с `7`.
Один legacy-реестр соответствует одной коллекции; Adapter проверяет её имя.
Это предотвращает потерю смысла данных при переводе.

Ошибка `OutOfMemoryError` не является рабочим статусом каталога: такие сбои JVM не
перехватываются. Под «все ошибки» здесь понимаются ошибки API и его рабочего вызова.

### 3.6. JUnit 5 с mock или stub

Stub — подставной объект для теста. Вместо настоящего каталога тест передаёт объект,
который запоминает аргументы и возвращает заранее известную квитанцию.

`AccessionTest` проверяет, что обычная приёмка передала 0 дней, карантинная — 30,
образец тот же, вызов был ровно один, результат не потерян. Ещё проверяется передача
общей ошибки через оба режима.

`LegacyCatalogAdapterTest` использует `StubLedger`, чтобы независимо воспроизвести
каждый статус и исключение. Отдельно проверяются реальные ограничения legacy API.
Mockito не обязателен: задание разрешает mocks **или stubs**, и здесь stubs написаны вручную.

`IntakeServiceTest` проверяет выбор из входных данных и расширение обеих сторон.
`CatalogIntegrationTest` проверяет настоящие каталоги, дубликаты и все шесть комбинаций.

### 3.7. UML именно своего кода

Открой `uml.png`. Стрелка с пустым треугольником означает наследование, пунктир с

## 5. Required Complexity Module — выбрать ровно один

Выбран **Dynamic implementor selection**. `IntakeService` читает
`specimen.collection()` и ищет каталог в `catalogs`:

```java
SpecimenCatalog catalog = catalogs.get(specimen.collection());
```

`botany` выбирает центральный каталог, `expedition` — журнал, `archive` — Adapter.
Клиент вводит предметные данные, а не `new LegacyCatalogAdapter(...)` для каждого запроса.
`Main` один раз регистрирует доступные зависимости; это не выбор конкретной реализации
за пользователя. Проверяются и стандартный, и карантинный режимы для всех коллекций.

Второй разрешённый вариант — **Two-way adapter**: перевод в обе стороны с доступом
к native-интерфейсу в другой части приложения. Здесь он не реализован, потому что
задание требует выбрать ровно один модуль.

## 8. Oral Defense — как объяснить один запрос

Запусти из папки проекта:

```powershell
mvn clean verify
java -jar target/museum-accession-1.0.0.jar quarantine archive 42 "Historic herbarium"
```

Путь запроса:

1. `Main` получает четыре строки и создаёт `Specimen`.
2. `IntakeService` по `archive` находит `LegacyCatalogAdapter`.
3. По `quarantine` создаётся `QuarantineAccession`, в неё передаётся найденный каталог.
4. `admit` вызывает `catalog.register(specimen, 30)`.
5. Adapter проверяет коллекцию и ID, кодирует название в UTF-8, вызывает
   `ledger.accession(30, bytes, 42L)`.
6. Ledger сохраняет запись и возвращает `1`.
7. Adapter возвращает `ARCHIVE-1`; результат проходит обратно через приёмку и сервис.

Поменяй только `archive` на `botany`: политика останется карантинной, а каталог сменится.
Поменяй только `quarantine` на `standard`: каталог останется, а длительность станет 0.
Именно это демонстрирует независимость двух измерений.

Данные живут в памяти: отдельный запуск создаёт новый каталог. Поэтому два запуска
с одинаковым ID не показывают дубликат; повторную регистрацию в одном экземпляре
проверяет `CatalogIntegrationTest`.

## Как читать исходники

Порядок: `Specimen` → `SpecimenCatalog` → `Accession` → два наследника →
`CentralCatalog` и `FieldJournal` → `LegacyLedger` → `LegacyCatalogAdapter` →
`IntakeService` → `Main` → тесты.

`record` — компактный класс данных с конструктором и методами доступа.
`implements` означает выполнение интерфейсного контракта, `extends` — наследование.
`throws CatalogException` сообщает, что вызывающий код должен обработать общий сбой.
`StandardAccession::new` — ссылка на конструктор: из переданного каталога создаётся
объект обычной приёмки. `Map` связывает ключ с объектом, например коллекцию с каталогом.

## Вопросы для самопроверки

Сначала ответь самостоятельно, затем сверь ответы ниже.

1. Где конкретно находится Bridge?
2. Почему Adapter — третий Implementor, а Ledger — не четвёртый?
3. Какие преобразования делает Adapter кроме смены имени метода?
4. Что произойдёт при `-3`? А при неизвестном `-99`?
5. Откуда программа узнаёт, какой каталог выбрать?
6. Как добавить приёмку с карантином 7 дней?
7. Почему можно создавать конкретные каталоги в `Main`, но нежелательно в `Accession`?
8. Почему это Bridge, хотя структура напоминает Strategy?
9. Почему ID `007` нельзя молча превратить в `7`?
10. Какое ограничение у демонстрации?

### Ответы

1. Ссылка `Accession.catalog` соединяет иерархию приёмок с интерфейсом каталогов.
2. Adapter реализует `SpecimenCatalog`; Ledger имеет другое API и скрыт внутри Adapter.
3. Извлекает ID, преобразует его в число, кодирует label в байты, меняет порядок,
   преобразует квитанцию и ошибки.
4. `UNAVAILABLE` и `INTERNAL` соответственно, в общем `CatalogException`.
5. Из `Specimen.collection()`, затем через реестр `IntakeService`.
6. Новый наследник `Accession` делегирует с 7 днями; передаём его factory в реестр.
   Пример есть в тесте расширяемости; существующие production-классы менять не нужно.
7. `Main` собирает зависимости; `Accession` должна работать с любым каталогом через контракт.
8. Нам нужны две независимые оси — правила приёмки и инфраструктура каталогов.
   Strategy обычно фокусируется на взаимозаменяемых алгоритмах одной операции.
9. Иначе разные исходные ID могли бы стать одним ключом старого реестра.
10. Хранение только в памяти и работа в одном потоке; после выхода записи исчезают.
